# TC-02 修复前页面创建失败复现

## 用例目标

复现首轮升级镜像 `sha-99799cd` 的 UI 问题：在 Sealos Desktop 中点击 `添加定时任务` 后，页面未进入编辑页，而是停留在空列表。

## 关联代码修改

本用例是修复前失败复现，对应后续修复点为：

- `src/utils/quota.ts`：新增 workspace quota 兼容处理。
- `src/pages/_app.tsx`：初始化时挂载兼容补丁。
- `__tests__/utils/quota.test.ts`：覆盖兼容返回和异常透传。

## 前置条件

- <TEST_NODE> 已升级到 `ghcr.io/sealos-apps/cronjob/cronjob-cluster:sha-99799cd`。
- Sealos Desktop 中可以打开 `定时任务` 应用。
- 当前用户 namespace 中没有已创建的 CronJob，页面处于空列表状态。

## 测试流程

1. 登录 Sealos Desktop。
2. 打开 `定时任务` 应用。
3. 在空列表页面点击 `添加定时任务`。
4. 观察页面是否跳转到 `/job/edit` 编辑页。
5. 查看页面错误表现。

## 期望结果

点击 `添加定时任务` 后应进入创建表单。

## 实际结果

复现成功，判定为失败用例。

- 页面仍停留在空列表。
- 点击后没有进入创建表单。
- 浏览器侧出现 `PAGEERROR Object`。
- Sealos Desktop 返回的错误信息为 `function is not declare`，说明当前 Desktop 没有暴露 `account.getWorkspaceQuota`，而页面把该兼容性问题当作阻断错误处理。
