# TC-05 集群健康、残留和镜像缓存复查

## 用例目标

完成修复验证后复查集群健康、旧配置残留和镜像缓存，确认当前环境只保留有效 `cronjob` 运行态。

## 关联代码修改

- `deploy/cronjob-entrypoint.sh`：清理旧 `cronjob-frontend` release、namespace、values，接管当前 `cronjob` 资源。
- `.github/workflows/build_from_sealos.yaml`：构建集群镜像时缓存当前运行时镜像。
- `deploy/images/shim/imagelist`：记录需要进入集群镜像缓存的附加镜像。

## 前置条件

- TC-01、TC-03、TC-04 均已通过。
- 当前运行镜像为 `ghcr.io/sealos-apps/cronjob/cronjob:sha-3aa827c`。

## 测试流程

1. 检查节点状态：
   - `kubectl get node -o wide`
2. 检查非 Running Pod 和非 Ready Deployment。
3. 检查 `cronjob` 应用资源：
   - Deployment、Pod、Service、Ingress。
4. 检查 UI 创建的用户 CronJob、Job、Pod 状态。
5. 检查旧资源残留：
   - active resources 中不能再出现 `cronjob-frontend`。
6. 清理未使用的旧镜像缓存：
   - `labring/sealos-cronjob-frontend:v5.1.2-rc5`
   - `sealos-apps/cronjob/cronjob:sha-99799cd`
7. 复查当前镜像缓存和 Pod 镜像。

## 期望结果

- 节点为 `Ready`。
- 无异常 Pod 和非 Ready Deployment。
- `cronjob` Deployment 为 `1/1`。
- 页面创建的 CronJob 有成功完成的 Job 和 Pod。
- 旧 `cronjob-frontend` 活跃资源无残留。
- 旧镜像缓存清理后，只保留当前 `sha-3aa827c` 运行镜像。

## 实际结果

通过。

- 节点 `<TEST_NODE>` 为 `Ready`。
- `non running pods` 和 `non ready deployments` 为空。
- `deployment.apps/cronjob` 为 `1/1`。
- 用户 CronJob `ui-smoke-<case-id>` 的 Job 为 `1/1`，Pod 为 `Completed`。
- active resources 中没有 `cronjob-frontend` 残留。
- 镜像缓存清理后保留 `sealos.hub:5000/sealos-apps/cronjob/cronjob:sha-3aa827c`。
